# 第一阶段前端改版：页面分类与实施步骤

> 本文记录第一阶段页面范围、执行顺序与实施进度。A1 已按 Trellis 任务实施基础样式及控制台页面接入，真实账号浏览器验收尚待完成；其余条目仍是规划，不表示已实现。

## 1. 目标与依据

**目标**：参考新版 Demo 重构普通用户端的布局、视觉层级和接入流程，复用现有业务接口，不引入新的积分、订阅、邀请或认证机制。

**架构原则**：保留 React、TypeScript、TanStack Router/Query、现有 Zustand 状态与组件体系。优先调整页面组合与展示，不把单文件 HTML 的全局状态、DOM 操作、hash 路由和模拟数据移植到正式项目。

**参考文档**：[整体改版分析](./frontend-subscription-demo-change-analysis.md)。

**对比依据**：当前源码与 `ZYY-AI-订阅版(2).html`。现有页面尚未进行完整运行态对比；本文中的新增路由与模块位置均为建议，不是已经存在的实现。

### 1.1 第一阶段必须守住的边界

- 不修改账户额度、扣费、预扣、结算、退款规则。
- 不新增永久积分、GPT 专项积分、7 天奖励释放等业务。
- 不上线自动续费授权与扣款，不承诺 Demo 中的套餐价格和赠送规则。
- 不新增短信、邮箱验证码直接登录及微信扫码身份体系。
- 不删除现有多模型密钥、分组、Auto 分组、IP 限制等能力。
- 不删除密码、Passkey、2FA、个人访问令牌等安全功能。
- 管理员页面不随用户端重构整体改版；共享组件变更必须验证管理员页面。
- 不修改部署脚本、支付通道配置或数据库结构。
- 保留项目要求保护的 new-api、QuantumNous 标识、版权和许可证信息。

### 1.2 “视觉对齐”不等于“业务照搬”

| Demo 内容 | 第一阶段处理 |
| --- | --- |
| 准备积分 | 使用现有账户余额/额度和充值入口，不虚构积分余额 |
| 一个密钥一个模型 | 新建简化流程可预选一个模型；保留旧多模型密钥和高级配置 |
| 订阅入口 | 指向现有钱包套餐区域，文案说明其实际功能；不假冒新订阅中心 |
| 邀请好友赚积分 | 保留现有邀请功能入口，不展示未实现的分级返奖与待释放金额 |
| 手机号、头像上传、发票抬头 | 未确认接口支持前不提供可保存的新表单 |
| 每次最低 1 积分 | 不使用该文案，除非未来服务端规则已实际落地 |
| 官网折扣和调用次数 | 只有数据、来源和计算口径明确时才展示，否则保留真实价格 |

- 新版订阅方案、用户“我的订阅”、权益排期。

- 双积分钱包、积分来源账本、待释放奖励。
- 独立邀请活动、阶梯奖励、终身邀请人补录。
- 新版验证码注册登录、手机号绑定与账号合并。
- 发票申请、进度、下载与开票后台。

**注意**：当前 `/subscriptions` 是管理员套餐管理入口，不能占用为用户“我的订阅”。
