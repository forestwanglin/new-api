## 1. 需求与边界

- 顶部菜单在「模型广场」之后增加「订阅」，路由 `/subscription`；公共页、工作台和移动导航复用相同入口数据。
- 视觉与简体中文文案来源：`c-dev/ZYY-AI-demo.html` 的 `#v-subscription`、`subPlanCard()`、`renderSubscription()`、`#subOrderModal`。
- 本次只有前端页面，不新增或修改后端、API、支付、积分、认证或部署功能，也不接入现有钱包订阅 API。
- 纯前端演示边界已经用户确认：不发生真实扣款或授权、不生成订单、不更新真实订阅/余额。

## 2. 实施步骤

1. 检查公共/工作台导航的数据源与 PublicLayout，确定复用共享 `useTopNavLinks`；不替换原有导航、语言、主题、公告和账号逻辑。
2. 新建独立 `subscription-demo` feature 和公开 `/subscription` 文件路由，生成类型安全路由树。
3. 以 Demo 为准录入三档套餐、月付和年付、常规积分和续费赠送说明；规则逐项保留，独立数据文件避免重复。
4. 组合项目现有 Button、Switch、Tabs、Dialog、Checkbox、Select。现有钱包组件会调用真实业务 API，因此不复用其数据层；复用通用交互而非另建弹层基础实现。
5. 添加仅订阅页作用域 CSS：1200px 容器、28px 横向边距、三列套餐、蓝色积分块和续费区域、规则区域；820px 以下单列，深色主题使用对应背景和边框。
6. 增加英文键、简体中文 Demo 文案及其他语言英文 fallback，不覆盖任何已有翻译；动态套餐权益和规则登记在 static-keys。
7. 测试套餐/积分、导航次序、确认前同意、开关互斥/取消、Escape、卸载重置及订单空态；执行类型、Lint、格式、构建和浏览器检查。
8. 同步 fork 定制登记并本地提交，不推送。

## 4. 演示交互与有意差异

- 页面与弹窗始终提示「仅为前端演示」，确认按钮为「确认演示」而非假装真实「确认支付」。
- 自动续费确认后只更新当前组件状态；同时仅允许一个套餐/周期被选中；切换新方案覆盖旧选择；关闭开关或管理区取消立即清除演示选择。
- 弹窗打开时重置同意勾选和支付方式；未勾选不能确认。取消/Escape 不开通演示设置。
- 单次购买不创建订单，不改变自动续费选择；确认只展示未实际支付或开通的提示。
- 不显示假余额、假到期日期、假权益生效状态，不把接口未加载说成真实「尚未订阅」。管理区使用「演示方案」等措辞，订单与发票为明确演示空态。
- 不建立 Demo 内的支付/积分账本、退款、合同排期、发票申请和客服系统；客服按钮只提示未接入。
- 状态不写 localStorage、不发订阅 API。页面卸载/刷新后清空；公共布局原有状态/品牌/通知请求保持原样，不属于订阅 API。
- `/subscription` 为前端公开入口，独立于后端模块开关；若模型广场被配置隐藏，订阅仍位于其逻辑位置（控制台之后、排行榜之前）。其他导航动态配置不变。
- 深浅主题沿用应用颜色，蓝色内容区域参考 Demo；弹层/开关/按钮/焦点遵循现有 UI 组件，因此不是独立 Demo HTML 的像素级克隆。
- 简体中文使用 Demo 文案；英文提供对应内容，其他语言新增键暂用英文 fallback，未宣称完成全部语言的人工翻译。
