# 手机验证码与微信手机号绑定

未登录入口使用全局登录弹窗，样式依据 `c-dev/ZYY-AI-demo.html`。公开弹窗仅保留微信扫码、手机号验证码。已有管理员密码登录保留在 `/sign-in?admin=true`，已有 TOTP/passkey 登录验证继续生效。

## 阿里云配置

1. 在阿里云短信服务申请审核通过的短信签名和验证码模板，模板变量使用 `${code}`。当前仅支持中国大陆 `+86` 手机号。
2. 在**后端启动工作目录的 `.env`** 或后端进程/容器的环境变量中配置下面的短信凭据（参考仓库 `.env.example`）。两个 AccessKey 值均不能为空；使用临时凭证时还需 `ALIYUN_SMS_SECURITY_TOKEN`。使用仅有短信发送所需权限的凭证，保存后重启后端，再进行下一步；不要写入前端环境、Git 或页面配置。
3. 进入**系统设置 → 身份认证 → 手机短信认证**，路径 `/system-settings/auth/phone-sms`，配置阿里云地域（默认 `cn-hangzhou`）、短信签名名称、短信模板编码（如 `SMS_...`），保存并开启手机号验证码登录。对应 options 键为 `phone.region`、`phone.sign_name`、`phone.template_code`、`phone.enabled`。
4. 先验证真实短信送达，再对外启用微信入口。微信公众号二维码、启用开关及验证码来源继续使用原系统的微信登录配置，无需修改 wechat-server。

后端 `.env` 示例（空值需替换为实际凭据）：

```dotenv
ALIYUN_SMS_ACCESS_KEY_ID=
ALIYUN_SMS_ACCESS_KEY_SECRET=
# 使用临时凭证时填写；长期 AccessKey 无需此项
# ALIYUN_SMS_SECURITY_TOKEN=
```

后端启动时通过 `godotenv.Load(".env")` 读取**当前工作目录**的文件，不是按可执行文件位置查找。已有进程环境变量优先于 `.env`；如果环境中已设置空值或旧凭据，需要同步更新。修改文件后必须重启后端，管理页面保存不会重新加载文件。

容器部署时，宿主机 Compose 项目目录的 `.env` 主要用于 Compose 变量替换，不会自动成为容器环境。当前镜像工作目录为 `/data`，仓库 `docker-compose.yml` 将 `./data` 挂载到 `/data`，因此可在宿主机 `./data/.env` 填写上述凭据供后端读取；也可通过现有容器环境配置渠道注入。其他部署方式应以实际容器工作目录、挂载及环境为准。

后端只公开短信是否可用，不返回 AccessKey。缺少签名、模板或凭据时不能开启；环境变量轮换后需要重启后端。所有实例需使用相同 `SESSION_SECRET`，确保认证摘要和浏览器关联在多实例间一致。

## 登录与约束

- 填写有效手机号及 5 位图形码后，页面等待 350 毫秒自动请求服务端验证，无需额外点击验证按钮；通过前获取短信按钮保持禁用。修改号码、图形码、刷新图片或关闭弹窗会取消当前验证并忽略旧响应；已提交的图形码不会自动重复尝试。图形验证码由服务端签发并验证，2 分钟有效、一次尝试；通过后才取得 2 分钟有效的单次短信发送授权。浏览器、手机号、微信待绑定流程均由服务端关联，直接绕过图形验证发送会失败。
- 短信为 6 位数字，5 分钟有效，最多 5 次验证尝试。成功仅可使用一次；同浏览器对同号码重新发送成功后，旧验证码失效。
- 发送间隔通过数据库持久化窗口保证至少 60 秒，实际为 60–90 秒，页面统一显示 90 秒。单手机号每自然日最多 10 次，单 IP 每小时最多 20 次（按 UTC 时间桶）。多个实例共享数据库执行限制。图形验证不能绕过限流。
- 发送授权在请求阿里云之前消费。供应商超时可能已经投递，系统不会自动重试；失败后需重新进行图形验证，并等待限流窗口结束。
- 手机验证后，已绑定账号进入共享登录流程；新号码仅在系统允许注册时创建账号。原封禁与额外认证策略继续执行。
- 微信验证后，未绑定手机号的账号只获得 10 分钟有效的待绑定流程，**不会签发正式会话**。微信 TAB 内完成手机绑定后再执行共享登录流程。手机号已属于其他账号时拒绝，提示使用其他手机号；不合并账号、余额或资产。
- 待绑定阶段关闭弹窗会丢弃客户端流程；重新登录重新验证微信即可。浏览器变化、账号封禁、认证版本撤销、过期和重放都会导致验证失败。

## 上线与回滚

迁移仅为已有 `auth_flows` 添加带默认值的 `attempts` 列；手机号归属使用已有 `external_identity_claims` 的唯一索引。无需填充用户手机号，已有微信账号下次新登录时要求绑定。已签发会话继续遵循原生命周期。

先配置短信并完成实际送达验证，再发布/开放微信绑定入口。如果关闭短信配置，未绑定手机的微信用户无法完成新登录；保留管理员恢复入口用于修复配置。回滚应用版本时保留新增列与身份记录，不自动删表或清理手机号归属。

本次实现通过模拟 HTTP 验证阿里云签名、请求及失败不重试；未持有真实凭据，未验证真实短信送达、签名/模板审核状态或阿里云账户额度。数据库矩阵和浏览器检查的实际结果记录在 `zyy-customization.md` Z042。
