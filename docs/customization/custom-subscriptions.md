# 自定义订阅后台

本功能独立于旧版订阅。管理员在“自定义订阅”（`/custom-subscriptions`）维护套餐与规则，布局和交互与用户、渠道管理页保持一致。公开订阅页读取后台已启用的套餐与全局规则，套餐按月付、年付分组；单次购买接入支付宝／微信支付，支付成功后同时增加旧 quota、发放套餐积分并生成订阅排期。

## 当前范围

主库使用 `custom_subscription_plans`、`custom_subscription_orders` 保存套餐与订单结构，另使用独立的 `custom_subscription_rules` 保存展示规则。管理员可维护套餐与规则列表、新增、查看、编辑、启停和删除。规则功能不修改既有套餐表和订单表结构。订单支持登录用户创建、本人状态查询和签名支付回调，订阅权益由既有履约模型生成。自动续费开关与赠送比例仅保存配置，不发起真实签约或扣款。

不创建默认套餐，不处理自动续费签约扣款、发票或退款；服务排期由独立的用户订阅实例管理。旧订阅 `/subscriptions` 保持原行为；公开页 `/subscription` 的套餐、价格与积分使用后台配置。积分消费链路不在本次范围。

## 套餐字段

| 字段 | 意义 |
|---|---|
| id / code / title / subtitle | 主键、唯一编码、名称、说明 |
| tier_code / tier_rank | 历史档位编码与等级，仅元数据，不参与订阅排期 |
| priority | 使用优先级，非负 int32，越大越优先；与展示 sort_order 独立 |
| billing_cycle / duration_months | month对应1个月，year对应12个月；实际服务时长分别固定为30天、365天 |
| currency / price_amount_minor | CNY与人民币分，整数保存 |
| paid_points / paid_point_type_id | 实付获得积分及现有point_types类型ID |
| bonus_points / bonus_point_type_id | 常规赠送数量与类型，零赠送类型为NULL |
| auto_renew_enabled | 自动续费是否启用；与用于展示的续费奖励配置独立 |
| auto_renew_bonus_bps / auto_bonus_point_type_id | 自动续费额外赠送基点比例及类型，1000为10%；未配置赠送时类型为NULL |
| benefits_json | 展示权益数组，不替代point_model_rules的使用范围配置 |
| enabled / sort_order | 是否启用、降序排列权重 |
| version | 版本号，更新时匹配并递增，拒绝覆盖其他管理员的新版本 |
| created_at / updated_at | Unix毫秒 |

未开启自动续费也可配置并展示续费奖励；关闭开关保留奖励比例和积分类型。奖励比例大于零时仍要求有效积分类型并检查潜在总积分溢出，比例为零时类型规范化为NULL。

额外赠送按 `floor((paid_points + bonus_points) × auto_renew_bonus_bps / 10000)` 计算，仅用于配置有效性和溢出检查，当前不会发放积分。积分类型从数据库读取，不写死GENERAL/GPT。金额及积分使用signed int64，API中ID、版本、金额和积分均使用十进制字符串，避免JavaScript精度损失。

## 订单字段

订单保留平台订单号、用户/套餐关联、成交版本与快照、档位/周期、应付/实付分、三类积分数量/类型、自动续费比例快照、支付方式/服务商/渠道交易号、预留授权与周期、支付/履约状态、既有积分业务单关联、退款汇总、脱敏渠道结果及毫秒时间。

唯一键为平台订单号、服务商与渠道交易号、授权与周期、积分业务单ID。未发生的渠道交易/授权/积分业务单使用NULL，可保留多条未支付记录。授权ID只是未来关联预留，本期不创建授权表。

存在订单或规则引用的套餐不能删除，可停用或先调整规则的适用套餐。规则关联写入与删除套餐使用同一套餐锁。创建订单与删除操作使用同一套餐锁并保存成交快照；订阅履约模型仅接受已有支付成功订单，不替代支付校验、订单创建状态机、积分发放或退款流程。

## 管理接口

全部要求登录管理员，PAT拒绝。与订阅管理页共用支付合规确认判断：只有已确认且条款版本为当前版本时，才允许新建、编辑、启停和删除；未确认、版本过期或尚未读到确认配置时显示相同提示并禁用写操作，列表与详情仍可查看。后端 POST/PUT/DELETE 复用既有合规校验，直接调用接口也不能绕过；已打开的表单和删除确认框在确认失效后停止提交。路径前缀 `/api/custom_subscription/admin/plans`：

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | 前缀 | 分页、keyword、enabled、billing_cycle筛选 |
| POST | 前缀 | 创建完整套餐配置 |
| GET | 前缀/:id | 查看详情 |
| PUT | 前缀/:id | 完整配置更新，携带version字符串 |
| DELETE | 前缀/:id | 无订单引用时删除 |

分页参数p默认1、page_size默认20且上限100；按sort_order、id倒序。keyword为名称/编码的字面包含匹配，%与_不作为通配符。返回标准success/message/data；列表data包含page、page_size、total、items与point_types目录。详情及写入返回单个套餐DTO，含三类积分的类型展示对象。

请求只接受配置字段；未知字段、尾随JSON、无效整数、未知类型、重复编码、过期版本和不匹配的周期均拒绝。显式false、0及NULL正确保存。套餐CRUD不会产生订单和账务记录。

## 公开套餐接口与页面

`GET /api/custom_subscription/plans` 无需管理员权限，无查询参数，返回标准 `success/message/data`，其中 `data.items` 为所有已启用套餐，按 `sort_order DESC, id DESC` 排序，不受管理员列表 100 条分页上限影响。

公开字段包括 `id`、`version`、`title`、`subtitle`、`billing_cycle`、`duration_months`、`currency`、`price_amount_minor`、`paid_points`、`paid_point_type`、`bonus_points`、`bonus_point_type`、`auto_renew_enabled`、`auto_renew_bonus_bps`、`auto_bonus_point_type`、`benefits`。类型对象仅含字符串 `id/code/name`；可选类型为 NULL。ID、金额、积分保持十进制字符串；不返回管理编码、档位、排序权重或审计时间；版本供下单时检测方案变更。

公开页按 `billing_cycle` 分成月付与年付，每条数据库记录独立显示，不拼接同档位的月付/年付记录。卡片与真实单次购买确认弹窗读取实际名称、说明、权益、价格和积分；自动续费奖励配置可以展示，但签约与自动扣款入口不可执行。积分使用 BigInt 精确计算，相同类型合并展示，不同类型分开列出；续费奖励沿用上述向下取整公式，不固定为 10%。

未配置套餐时显示空状态，接口或配置解析失败时显示错误并允许重试，不恢复静态示例。规则区继续读取已启用的全局规则并保留格式。保持既有 CSS 和按周期的卡片布局；公开查询不产生账务写入；登录用户主动确认购买后创建订单并跳转支付。

## 迁移与回滚

启动主库迁移时增量建表，不改日志库，不访问生产数据。回退代码时保留新表及数据，不自动DROP。数据库验证使用隔离真实实例；代表性旧余额样本不是完整最新正式发行版数据库升级证明。实际验证命令、版本、覆盖限制见定制登记。

## 规则管理

自定义订阅中的规则入口复用管理列表、工具栏、完整分页和右侧抽屉。规则支持新建、详情、编辑、启停、排序与删除；未确认支付合规或条款过期时，只允许读取，直接 API 写入同样拒绝。

| 字段 | 意义 |
|---|---|
| id | 规则主键，API 为十进制字符串 |
| plan_id | 适用套餐；NULL 表示全局规则 |
| rule_key | 全局唯一规则标识，创建后不可更改 |
| title | 对用户展示的纯文本标题 |
| content_json | 段落和文本片段组成的正文，片段内保存样式 |
| enabled / sort_order | 启用状态与展示权重 |
| version | 乐观锁版本，拒绝过期覆盖 |
| created_at / updated_at | Unix 毫秒时间 |

正文支持分段、文本加粗、文字颜色、背景高亮及实时预览。颜色使用六位 HEX，样式只允许明确字段；HTML 和任意 CSS 不会执行。规则文案只控制展示，不改变实际价格、积分发放或续费逻辑；价格、积分类型及奖励比例等文案需与实际配置保持一致。

管理接口前缀 `/api/custom_subscription/admin/rules`，GET/POST 操作列表与创建，GET/PUT/DELETE `/:id` 操作单条；更新携带 version。公开 GET `/api/custom_subscription/rules` 返回已启用全局规则；指定有效且启用的 plan_id 时，同时返回对应套餐的规则。最小版规则标识全局唯一，不支持同名规则覆盖或一条规则绑定多个套餐。

公开页套餐使用数据库真实 ID，规则区保持展示已启用全局规则。套餐专属规则仍可配置和通过 `plan_id` 查询，本次不增加套餐专属规则展示区域。

原有 11 条规则及蓝色加粗内容通过一次性事务迁移保留。重复启动不会覆盖编辑内容，也不会恢复已删除或已停用规则；规则全空时显示空状态，读取失败显示错误和重试入口，不回退到静态规则。规则尚未关联订单，允许正常删除；不会为规则操作改写历史订单快照。

回退旧前端代码后会重新使用当时内置的静态规则，这是代码回滚的展示差异；规则表和一次性迁移标记保留，便于再次升级时恢复管理员配置。


## 优先级订阅与到期调度

主库新增 `custom_user_subscriptions`、`custom_user_subscription_states`、`custom_subscription_events`；不写独立日志库，不改变旧版订阅或 relay 额度计费。

- 每笔已支付订单履约一次，`order_id` 唯一约束防重复。套餐和订单新增 `priority`，默认 0。旧后台请求省略优先级时，新建为 0，更新保留原值；显式 0 正常保存。旧档位字段保留，仅作元数据。
- 调度顺序为 `priority DESC, purchased_at ASC, id ASC`，购买时间取订单支付成功时间。每次购买保持独立实例；不合并相同套餐，不读取当前套餐来覆盖历史订单。
- 订单独立快照字段是调度依据，`plan_snapshot` 保留审计。套餐后续调价、改优先级或停用不影响已购实例。首次激活从实际履约开始，不将尚未生成的权益追溯到历史支付时间。
- 月付固定 30 天，年付固定 365 天，每天 24 小时；年付不按 `12*30` 计算。总时长、剩余时长及所有时间戳使用 signed int64 毫秒并检查溢出。
- 每用户最多一个 active。高优先级购买会暂停当前实例，保存剩余时长；暂停实例不计时。恢复后使用剩余时长，不重新赠送完整周期。相同优先级按支付时间与实例 ID 排序。
- `remaining_duration_ms` 是最近激活基点的持久化余额；active 的实时剩余时间由 `active_until_at - observed_at` 得出。无需每秒写库。`paused/active/expired/cancelled` 为实例状态，未首次激活的实例也属于 paused。
- 用户状态行是并发串行化入口，事务内同步当前指针、实例和事件。SQLite 在读队列前先取得数据库写锁；MySQL/PostgreSQL 使用共享锁工具及一致锁顺序。进程内防重入不代替数据库一致性。
- 到期按原 `active_until_at` 切换：A 在10:00到期、任务10:05执行时，下一份从10:00开始计时。停机后连续推进已耗尽的实例，直至当前有效实例或队列为空；不请求 API 也会消耗 active 服务时长。
- 新后台任务启动后立即扫描，再每10秒扫描到期用户；使用索引与分批处理。多个 worker 并发扫描仍需用户事务重新确认。
- `GET /api/custom_subscription/self` 使用当前会话用户身份，拒绝用户筛选参数及 PAT，查询时执行同一到期校正。响应显式列出订阅状态、优先级和时长，ID/时长使用十进制字符串，不返回订单渠道载荷。
- 事件保留业务生效时间和系统记录时间、状态及剩余时长变化；同一事务可写多次切换事件，重试不重复履约或转换。
- `FulfillCustomSubscriptionOrder` 保留仅处理已支付订单服务时长的公开契约；真实支付通过统一结算事务内的履约入口调用。完整支付成功要求支付状态、积分交易关联及权益履约标记同时成立。`ReconcileCustomUserSubscriptions` 为权益查询提供到期校正。
- 模型提供按用户校验归属的取消方法；不新增用户取消/退款 HTTP 接口，也不推定退款、积分冻结或额度耗尽自动降级政策。

迁移为增量建表/加列，不自动回填历史已支付订单或批量创建权益。回滚代码时保留新增表、列、实例和事件。验证使用隔离三数据库，具体命令及覆盖限制记录于定制登记与 Trellis 任务验证记录。


## 单次购买与支付结算

- `GET /api/custom_subscription/payment_methods` 返回当前配置且支付合规可用的 `alipay`／`wxpay`，不返回网关密钥。前端展示为支付宝／微信支付。
- `POST /api/custom_subscription/orders` 要求用户会话、现有 Origin 防护与限流；请求只有字符串 `plan_id`、`plan_version`、`payment_method`、`request_id`。价格、用户身份、积分和优先级均由后端决定。相同用户和请求标识只能创建一笔订单；冲突负载拒绝。
- `GET /api/custom_subscription/orders/:trade_no` 仅返回当前用户自己的安全状态 DTO，PAT 拒绝，不返回快照、渠道载荷或签名。
- 创建事务同时持久化 `top_ups` 与 `custom_subscription_orders`；后者新增唯一可空 `top_up_id`、用户内唯一可空 `checkout_request_id`、整数 `quota_to_credit` 快照。旧记录保持 NULL／0，不自动补发。
- `top_ups.business_type=custom_subscription` 标识用途，普通钱包回调与管理员充值补单不得单独完成这类订单。旧记录为空字符串，仍走原钱包逻辑。
- 订阅实付为 plan 的整数人民币分，不应用钱包预设充值折扣或充值最低额。quota 单独使用下单时配置计算：`round_half_away((price_amount_minor / 100) / Price / topup_group_ratio * QuotaPerUnit)`，零组倍率沿用旧规则视为1；严格校验配置与钱包上限并保存结果，后续配置变化不改订单。积分直接取套餐快照，不从 quota 或实付反推。
- 旧 `top_ups.amount` 是整数充值单位，无法表达订阅精确兑换结果，订阅订单保留0；钱包历史按用途显示“订阅购买”及原有实付金额，避免显示成0额度充值。实际 quota 以 `quota_to_credit` 为准。
- GET／POST `/api/custom_subscription/epay/notify` 与 `/return` 验证签名、商户、成功状态、订单、支付方式与精确金额。拒绝重复参数或混合来源；不把任意渠道字段／签名保存到业务载荷。浏览器无签名成功标识不能发放余额、积分或权益。
- 统一主库事务先取得用户订阅状态锁，再锁订单及充值记录，增加 quota、创建积分交易、按类型更新账户及 `point_ledger`、更新两单支付状态、创建订阅排期和事件。任何一步失败全部回滚；成功后刷新 quota 缓存并记录原有充值审计。积分账户按类型ID稳定排序，检查余额／版本溢出。
- 积分业务键为 `custom-subscription:<order_id>:credit`，付费与普通赠送积分按各自类型发放；同类型合并到账，不发自动续费奖励。交易、账户版本流水、支付关联和订阅订单唯一约束共同防重。暂停／恢复不再发积分。
- 本地待支付30分钟过期，主节点现有10秒任务分批关闭待支付记录；本地过期不代表第三方未收款。仍接受经过验证的延迟成功通知并完整结算。SDK未提供主动查单接口，本次恢复依赖支付平台通知重试和签名支付返回；不声称具备主动平台对账能力。
- 前端复用登录弹窗，登录后恢复所选方案；真实确认展示固定30／365天及实际积分类型。通过钱包表单方式跳转支付，返回后只查询本人订单，最多每2秒查询30次并支持手动／窗口聚焦刷新；服务器确认履约后刷新 quota 和订阅。自动续费、发票和完整订单历史暂不可用。

数据库验证覆盖隔离 SQLite、MySQL、PostgreSQL，现有表升级样本与重复迁移；真实支付仍需商户环境联调。回滚仅回退代码并保留新列和全部账务，不删除支付、积分或订阅记录。
